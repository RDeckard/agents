# Agents

A Rails app for interacting with [Claude Managed Agents](https://docs.anthropic.com/en/docs/agents). Discovers your existing agents via the Anthropic API, lets you start sessions, chat in real time, and retrieve HTML reports generated by the agent.

## Quick start

```bash
bundle install
bin/rails db:create db:schema:load db:seed
bin/dev
```

Default admin user created by seed: see `db/seeds.rb`. Requires `ANTHROPIC_API_KEY` set via `rails credentials:edit` (under `anthropic.api_key`) or as an env var. You also need at least one **agent** and one **environment** created on [platform.claude.com](https://platform.claude.com) or via the API.

## Stack

| Layer | Choice | Why |
|-------|--------|-----|
| Language | Ruby 4.0 | |
| Framework | Rails 8.1 + Hotwire (Turbo + Stimulus) | SSE streaming via ActionController::Live, Stimulus for client-side reactivity |
| Database | PostgreSQL | Render-native, production-ready |
| CSS | Tailwind via `tailwindcss-rails` | No Node build step |
| Asset pipeline | Propshaft + importmap | No bundler, JS via ESM |
| Auth | Sorcery | Email/password login, no public signup |
| Admin | Administrate | Dashboard at `/admin` for managing all records |
| Anthropic SDK | `anthropic` gem (~> 1.35) | Managed Agents beta (`managed-agents-2026-04-01`) |
| Markdown | Redcarpet (server-side) + marked.js (client-side) | Rendering agent messages |
| Tests | RSpec + FactoryBot + WebMock | All Anthropic calls stubbed, no API key needed |
| Target deploy | **Render** (web service + PostgreSQL) | Persistent process = no SSE timeout limit |

### Why Render, not Vercel

Managed Agent sessions stream events via SSE and can run for 10+ minutes. Vercel serverless functions have hard timeouts (5 min hobby, 13 min pro) and bill for memory during the entire connection. A persistent Render web service has no timeout constraint and bills a flat monthly rate.

## Architecture

### Authentication & authorization

- **Sorcery** handles email/password authentication. All routes require login except `/login` and `/up`.
- **No public signup** — users are created via the admin dashboard (`/admin/users`) or `rails console`.
- **Admin flag** — `User#admin?` controls access to the admin dashboard and visibility of all sessions/reports.
- Regular users only see their own sessions and reports. Admins see everything, including unowned records.

### Anthropic integration

The app is a **thin SSE proxy** between the browser and the Anthropic Managed Agents API:

```
Browser ←── EventSource (SSE) ──→ Rails ←── SSE ──→ Anthropic
        ──→ fetch POST          ──→      ──→ POST
```

- **Agents and environments** are created/managed on platform.claude.com (or via API). The app discovers them dynamically via `GET /v1/agents` and `GET /v1/environments`.
- **Sessions** are lightweight bookmarks: only `anthropic_session_id` and `user_id` are stored locally. Title, status, and agent info come from the Anthropic API at request time. When listing sessions, unknown Anthropic sessions are synced as unowned bookmarks (visible to admins only).
- **Events flow**: Rails opens an SSE stream to Anthropic (`GET /v1/sessions/{id}/events/stream`), re-emits each event to the browser as SSE, and the Stimulus controller updates the DOM in real time.
- **Messages**: the browser POSTs to Rails, which forwards to Anthropic (`POST /v1/sessions/{id}/events`).
- **Reports**: agents write HTML files to `/mnt/session/outputs/`. Reports are persisted to the database (deduplicated by `anthropic_file_id`) at two moments: when the SSE stream goes idle, and when a session page is loaded. Reports survive session deletion (`session_id` is nullable). Users can list their reports independently at `/reports`.

### Data model

```
User (optional)
├── has_many :sessions    (nullified on user delete)
└── has_many :reports     (nullified on user delete)

Session (bookmark)
├── belongs_to :user      (optional — nil for unowned/synced sessions)
├── has_many :reports     (nullified on session delete)
└── anthropic_session_id  (the real session lives on Anthropic's side)

Report
├── belongs_to :session   (optional — survives session deletion)
├── belongs_to :user      (optional)
├── anthropic_file_id     (unique — deduplication key)
├── filename
└── content               (HTML text, served raw)
```

### SDK quirks (Ruby gem v1.35)

- Event `type` fields are **Symbols** (e.g. `:"session.status_idle"`), not strings. Always `.to_s` before comparing.
- `event.content` can crash on `agent.tool_result` events with empty blocks. Use `event[:content]` (hash-style access) to get raw unparsed data.
- `files.list(scope_id:)` needs both beta headers combined: `request_options: { extra_headers: { "anthropic-beta" => "managed-agents-2026-04-01,files-api-2025-04-14" } }`. Passing `betas:` as a parameter doesn't merge correctly.
- `files.download` returns a `StringIO`, not a string. Call `.read` on it.
- Method names differ from docs: `stream_events` (not `stream`), `send_` (not `send`), `retrieve` takes a positional arg (not keyword).

## What works

- Agent listing and detail (from Anthropic API)
- Session creation, live chat with SSE streaming
- Session listing with live status from API
- Event history on session reload (via `events.list`)
- Markdown rendering (server + client side)
- HTML report persistence and serving (deduplicated, survives session deletion)
- User-scoped sessions and reports (regular users see only their own)
- Authentication (Sorcery, email/password, no public signup)
- Admin dashboard (Administrate) with "View in app" links for sessions and reports

## What's not done yet

- Render deployment config (`render.yaml`)
- SSE reconnection with event consolidation (recover from dropped connections)
- Tool confirmation UI (`always_ask` permission policies)
- Custom tool round-trips (host-side execution)
- File upload to sessions
- GitHub repository mounting
- Session status sync when no stream is active (polling or background job)
